# Проект 3. Разбор журналов веб-сервера

Участники: Barsbek, Nursultan, Kayratbek, Alihan, Bektur, Ainazik (уровень <...>, блоки A, B, C)

## Запуск (чистая Ubuntu, одной командой)
    ./run.sh

## Файлы
- gen_logs.py: генератор 40 логов по 15000 строк
- errors.sh: блок A.1
- count.py, strace_wc.txt, strace_py.txt: блок A.2
- parse_fork.py: блок B (os.fork + os.pipe)
- parse_modes.py: блок C.1-C.2 (pipe / shared_memory / временные файлы, Ctrl+C)
- outage.py: блок C.3

## Результаты
- Всего 600000 запросов, 5xx: 3374. Больше всего в access_02.log (432).
- Доля 5xx по путям: /api/pay 0.86%, остальные около 0.5%.
- Сбой: /api/pay, 2026-10-14 06:40:07 - 07:29:57.
- Время при N=1, 2, 4: 0.51 / 0.35 / 0.19 с.
- Три способа (N=4): pipe 0.183 c, shm 0.189 c, file 0.168 c.
- Зомби после работы: нет (ps_check.txt пуст). После Ctrl+C: нет процессов, сегментов в /dev/shm и файлов в /tmp.

## Выводы
- strace: у wc главный вызов read (большие блоки), у Python добавляются вызовы запуска интерпретатора (openat, mmap, newfstatat), поэтому вызовов в разы больше.
- Ускорение при N=4 около 2.7x при 12 ядрах: мешают накладные расходы fork, JSON и чтение с диска.
- Способы возврата результата дают почти одинаковое время, так как результат маленький, а основная работа это чтение логов.
- Сбой находится по минутам с долей 5xx выше порога, а не по первой и последней ошибке: фоновые 500 есть всю неделю (~0.5%).
- Зомби нет, потому что родитель вызывает os.waitpid для каждого ребёнка.
